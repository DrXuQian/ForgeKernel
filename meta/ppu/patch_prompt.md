# PPU milestone revision

## Inputs

- Diagnosis: {DIAGNOSIS_PATH}; candidates: {CANDIDATES_PATH}
- Milestone: {MILESTONE_PATH}; permitted oracle: {ORACLE}
- Policy: {META_MILESTONE_PATH}; template: {MILESTONES_TEMPLATE_PATH}
- Target generation: {KB_ARCH}

Fix the diagnosed defect while preserving unrelated accepted decisions.
Follow the shared milestone schema, five-tuples, DAG, phase order, coupled
groups and gate contracts. Recheck relevant historical lessons against the
new native evidence. Keep operator implementation bodies out of the milestone.

An architectural change returns to M0. Structural or split reopens require
the diagnosis's measured reopen_price; assumptions and static code counts are
not measured prices. Keep the gate payoff schedule explicit, withdraw stale
prices and record exact changed entries so unaffected work remains valid.
Use native ACU/ISA evidence and the selected target's resource semantics.
Do not pin compiler allocations to a historical card's observed values.

## Output

Edit the milestone file first, then report:

    patch_class: additive | structural | split | kb-example
    changed_entries: [<exact changed decision/section ids>]
    gate_contract: <allowed per-gate regression and where payoff occurs, if needed>
    patch: <summary of the actual edit>
    notes: <evidence, scope and changes to the Worked Example>
